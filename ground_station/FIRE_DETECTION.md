# 火源识别模块交接说明

## 1. 目标

当前模块用于比赛原型中的火源检测，支持两类目标：

- 真实画面中的明显可见明火；
- 2023 年 G 题场地中的实心红色圆形模拟火源。

它直接处理 AMB82 图传帧，在画面中绘制火源候选框，并将连续帧
确认后的结果写入地面站事件中心。

核心实现位于 `fire_detector.py`，与 Qt 界面解耦。

## 2. 识别流程

可见明火分支依次执行：

1. 高斯滤波抑制相机噪点；
2. HSV 色域筛选红、橙、黄色候选像素；
3. BGR 通道关系排除蓝灰背景；
4. 高亮核心检测，寻找黄白色火焰中心；
5. 形态学开闭运算合并碎片；
6. 轮廓面积、密度、亮核比例和形状联合评分；
7. 输出边界框、中心像素、面积和置信度。

模拟火源分支依次执行：

1. 提取高饱和度红色区域；
2. 过滤面积过大的红色区域，因此不会把起飞区当作火源；
3. 计算轮廓圆度、最小外接圆填充率和长宽比；
4. 只保留小面积、近圆形、实心的红色标志。

事件确认规则：

- 候选置信度不低于 68%；
- 连续 3 帧满足条件才生成事件；
- 同类事件生成后冷却 8 秒。

实时框可以单帧显示，事件中心只记录确认后的结果。

为适应 AMB82 720p/15 FPS 图传、算法约 6 FPS 推理频率和纸面反光：

- 普通候选框短暂丢失时保留约 1.6 秒；
- 连续帧确认后的火源框加粗并保留约 6 秒；
- 小目标框具有最小屏幕显示尺寸，避免缩放后看不见；
- 每次确认火源时，最近事件中心会红橙闪烁并保留红色事件卡片。

为降低 CPU 占用，720p 原始帧会缩小到 640 像素宽后执行识别，检测结果再按比例映射回 1280×720 主画面，因此显示清晰度不会因推理缩放而下降。

## 3. 数据流

```text
AMB82Camera
    -> CameraThread
    -> FireDetector.detect(frame)
    -> VideoCanvas 实时框选
    -> FireConfirmationTracker
    -> DetectionEvent
    -> 最近事件 / 完整事件 / 系统日志
```

## 5. 参数调整

`FireDetectorConfig` 中的主要参数：

- `min_confidence`：单帧候选最低分数，默认 0.58；
- `min_area_ratio`：最小轮廓面积占画面比例；
- `max_area_ratio`：最大候选区域比例；
- `morphology_size`：形态学核尺寸。

`FireConfirmationTracker` 中可以修改连续帧数、确认阈值和冷却时间。

调参时应同时准备：

- 不同距离、亮度和角度的真实火焰；
- 红色标志、橙色物体、夕阳等负样本；
- AMB82 实际压缩质量下的图像。

不要只根据内置示例提高置信度。

## 6. 已知限制

- 不检测纯烟雾、温度或隐藏火源；
- 暖色灯光、夕阳和大面积红橙物体可能误报；
- 红色圆形日常物体可能被模拟火源分支识别；
- 极小、过曝或严重运动模糊的火焰可能漏检；
- 当前置信度是规则评分，不是深度学习概率；
- 检测框位置是图像坐标，地理位置暂用无人机当前遥测坐标。

## 7. 后续升级建议

后续建议采集比赛现场数据，训练轻量目标检测模型，并通过 OpenVINO
部署。只需让新检测器继续返回 `FireDetection` 列表，地面站显示、
连续帧确认和事件记录逻辑可以保持不变。
